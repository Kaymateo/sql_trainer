# SQL 训练场 · 复杂 SQL 面试训练平台

一个跑在本机的 SQL 刷题平台：**随机出题 + 自动判题 + 错题本 + 八股自测**，专门练大数据开发面试里的复杂 SQL（窗口函数、连续区间、留存漏斗、行列转换、拉链表、口径拆解）。

数据是真的、判题是真的：每道题出题时用**随机种子生成一套全新的业务数据**，再用参考解在同一套数据上算出标准答案，你的 SQL 结果和它逐行对拍 —— 所以**背答案没有任何用**，每次都是新的数据、新的阈值。

---

## 快速开始

```bash
cd ~/sql_trainer
./run.sh              # 首次会自动建 .venv 并装依赖（duckdb + pyarrow）
# 或指定端口
./run.sh 3000
```

浏览器打开 **http://localhost:3000**（在宿主机上访问：http://172.16.105.2:3000）。

手动启动：

```bash
.venv/bin/python app.py 3000
```

依赖只有两个：`duckdb`（分析型 SQL 引擎）和 `pyarrow`（批量灌数据用，比逐行 insert 快 190 倍）。

## 出题与判题原理

```
随机种子 ──► 生成全套业务数据（9 张表，确定性：同种子 = 同数据）
         ├─► 参考解执行 ──► 标准答案（与数据永远一致）
         └─► 用户 SQL 执行 ──► 结果集
                                  │
                       多重集对拍比较（行序、列序不计）
                                  │
        ┌──────────────┬──────────┴───────────┬──────────────────┐
     列数不符        行数不符             内容有差异          完全一致 → 通过
   （提示列数）  （提示缺哪些行+重复行）  （给出参考值 vs 你的值对比例子）
```

**随机化的维度**：数据种子、TopN 的 N、品类子集、阈值、间隔天数、快照日期、限定用户数、时间窗口起点…… 所以同一道题每次做都是不一样的题。

**判定规则**：行顺序和列顺序都不计（面试里通常也不影响），但**列数和结果集内容必须一致**；输出会明确告诉你差异在哪，例如「你返回 5 行，参考结果 10 行。参考结果中有而你没有的行，例如：('家居日用', '苏泊尔保温杯46', '954.00')」。

## 怎么加新题

在 `bank/` 下任意 `ex_*.py` 文件里加一个 `Exercise(...)` 即可，重启服务自动生效：

```python
Exercise(
    id="my_new_exercise",           # 唯一 id
    category="窗口函数与排名",        # 必须是 bank.CATEGORIES 里已有的分类
    difficulty=2,                    # 1 基础 / 2 进阶 / 3 挑战
    title="每城市销售额 TopN 的商品",
    knowledge=["row_number", "分组排名"],
    tables=["dwd_order", "dim_user"],   # 需要哪几张表（只建这些表，省内存）
    params=lambda r: {"top": r.choice([2, 3, 5])},   # 随机参数（r 是 random.Random）
    prompt="""统计前 {top} 名…""",      # {参数} 会被渲染；**加粗** 与 `代码` 会渲染样式
    solution="""SELECT … LIMIT {top}""",  # 参考解，必须用同一套参数
    hints=["思路…", "关键语法…", "易错点…"],
    notes="""考点讲解（支持 Markdown 表格、代码块）""",
)
```

要点：
1. **参考解必须能用同一套参数跑通**，它就是标准答案的来源。
2. 排序要带**兜底键**（如 `ORDER BY cnt DESC, user_id`），否则并列时结果不稳定、判题会随机失败。
3. 涉及条件的过滤要保证**结果非空**（比如限定 topN 时要确定数据里确实有那么多组）。
4. `sql_` 前缀的参数（如 `sql_in_cats`）只用于拼装参考解，不会出现在题目文本里。

改完题库后跑自检：

```bash
PYTHONPATH=~/sql_trainer .venv/bin/python tests/test_bank.py 8
```

## 安全护栏

平台只读，且禁用了外部访问：

- 只允许单条查询语句（`SELECT` / `WITH` / `FROM …` / `PIVOT`），拒绝 DDL、DML、`ATTACH`、`COPY`、`INSTALL`、`PRAGMA`、多语句拼接；
- 关键词按**词边界**匹配，函数形式也拦得住（`read_csv(...)`、`glob(...)`、`parquet_scan(...)` 等都在黑名单里），并且额外拦截 `FROM '/路径'` / `FROM 'data.csv'` 这类把文件当数据源的写法；
- DuckDB 连接级 `enable_external_access=false` —— 读本地文件、访问网络、安装扩展全部被拒（双保险：文本层拦一道，执行层再拦一道）；
- 查询 20 秒超时自动中断（防笛卡尔积卡死），结果集有行数上限；
- 超时后自动丢弃该实例，下次访问用同一种子重建，数据完全一致；
- 误伤已排查：字符串里带斜杠的正常查询（如 `STRFTIME(dt,'%Y/%m/%d')`）不受影响。

## 常见问题

**Q：为什么用 DuckDB 而不是 MySQL/Hive？**
DuckDB 是分析型（OLAP）引擎，窗口函数、`QUALIFY`、`PIVOT/UNPIVOT`、`list/struct`、`GROUPING SETS` 全部原生支持，最接近 Hive/Spark SQL 的分析场景；同时零部署（进程内嵌），不用起集群。已注册 Hive 风格函数别名（`nvl`、`datediff`、`date_sub`、`collect_list`、`get_json_object`、`size`），降低方言切换成本。

**Q：DuckDB 语法和 Hive/Spark 有差异怎么办？**
每题讲解里都给了 **Hive 对照写法**（`date_format`、`collect_list`、`explode`、`LATERAL VIEW`、`concat_ws` 等），练的是思路和 SQL 结构，方言差异看讲解即可。

**Q：能重置进度吗？**
删掉 `data/progress.db` 重启即可（只影响进度记录，题库不受影响）。

**Q：想换题目数据规模？**
`bank/*.py` 里 `Exercise(scale=...)`，默认 1.0；填 2.0 数据量翻倍（服务内存占用也会涨）。
